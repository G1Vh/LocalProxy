# LocalProxy

Селективный прокси для Windows: домены из списка идут через выбранный канал (HTTP/SOCKS5-прокси или
VPN-туннель WireGuard / AmneziaWG / SSTP), всё остальное — напрямую. Приложение живёт в трее, настраивается
в окне.

Два режима:

- **Весь трафик (TUN)** — по умолчанию. Виртуальный адаптер забирает трафик всех программ, и правила действуют
  для любой из них: браузеров с прокси-расширениями, клиентов баз данных, RDP, игр, голоса Discord.
- **Системный прокси** — без прав администратора: правила видят программы, которые ходят через системный прокси
  (PAC), `HTTP_PROXY` или настроены на SOCKS5 вручную. Для остальных есть проброс портов.

## Возможности

- **Правила по доменам**: «домен и поддомены», «только точно», маска (`*` и `?`), подсеть (`149.154.160.0/20`)
  для программ, которые ходят по IP. Действие правила — «через канал» или «напрямую» (исключение).
  Если подходят несколько правил, побеждает самое конкретное.
- **Правила по программам**: `discord.exe` (или маска, или полный путь) — весь трафик программы идёт по правилу,
  куда бы она ни обращалась; такое правило важнее правил по адресам. В режиме TUN программа известна
  у каждого соединения, в режиме прокси — только у программ, которые ходят через LocalProxy.
- **Готовые наборы доменов** — OpenAI, Anthropic, GitHub, Gemini, YouTube, Telegram, Discord, Netflix. Набор — это подписка:
  список обновляется с GitHub без обновления программы, домены добавляются и убираются сами.
- **Каналы**: HTTP-прокси, SOCKS5-прокси, WireGuard и AmneziaWG (конфиг `.conf` вставляется как есть),
  SSTP (Windows RRAS, MikroTik, SoftEther; вход по MS-CHAPv2 или PAP, самоподписанный сертификат — по отпечатку).
  VPN-туннели поднимаются внутри программы: без драйверов, прав администратора и системного VPN-адаптера.
  Кнопка «Проверить» показывает, работает ли он.
- **Раздельное туннелирование**: у правила или набора может быть свой канал, остальные идут через канал
  по умолчанию. Все используемые каналы подключены одновременно.
- **Если канал недоступен** — его домены по умолчанию блокируются (чтобы не утечь мимо туннеля); можно
  переключить на «пускать напрямую». Через другой канал они не идут никогда. Иконка в трее меняет цвет,
  приходит уведомление.
- **Режим TUN**: TCP и UDP всех программ идут через правила; имена, которые знает только канал
  (`mysql.office.lan`), тоже работают — их разрешает DNS на той стороне. При смене сети (Wi-Fi вместо кабеля)
  всё переключается само. Ping отвечает по-настоящему, но идёт напрямую.
- **Входы**: HTTP, HTTPS (CONNECT) и SOCKS5 на одном порту, включая UDP через SOCKS5.
- **Проброс портов** (в режиме системного прокси) для программ, которые не умеют прокси: `127.0.0.1:13306`
  ведёт к `mysql.office.lan:3306` через выбранный канал.
- **Подключения и статистика**: лента соединений с программой, маршрутом и ошибками, трафик по адресам (TCP и UDP),
  кнопка «+ в правила» прямо из ленты.
- **Автозапуск** при входе в Windows (свёрнутым в трей), без батников.
- **Автообновление** с GitHub Releases: программа сама находит новую версию, ставит по кнопке.
- Предупреждение, если расширение браузера (Runet Censorship Bypass, TTV LOL и т. п.) задаёт свой прокси:
  в режиме прокси оно перекрывает правила целиком, в TUN — для сайтов, которые расширение ведёт через себя.

## Установка

Скачайте `LocalProxy_X.Y.Z_x64-setup.exe` со страницы [Releases](https://github.com/G1Vh/LocalProxy/releases/latest)
и запустите. Права администратора не нужны: программа ставится для текущего пользователя.
Нужны Windows 10/11 x64 и WebView2 (в Windows 11 уже есть, установщик при необходимости докачает).

Дальше:

1. Вкладка **Каналы** → добавьте прокси, вставьте конфиг WireGuard/AmneziaWG или укажите SSTP-сервер → «Проверить».
2. Вкладка **Правила** → отметьте нужные наборы и/или добавьте свои домены. Если каналов несколько, в колонке
   «Куда» (и рядом с набором) выберите, через какой идти; без выбора — через канал по умолчанию из шапки окна.
3. Переключатель вверху окна — **Вкл**. В режиме TUN при первом включении Windows один раз спросит права
   администратора: ставится служба «LocalProxy TUN». Отказались — программа работает в режиме системного прокси.

Закрытие окна сворачивает программу в трей; выход — из меню иконки в трее.

### Что программа меняет в Windows

Пока прокси включён, в настройках прокси пользователя прописан адрес PAC-скрипта
(`http://127.0.0.1:<порт>/proxy.pac`), а при отмеченной галочке — переменные `HTTP_PROXY`, `HTTPS_PROXY`,
`NO_PROXY` для консольных программ. Прежние значения сохраняются и возвращаются при выключении, выходе,
обновлении и удалении программы, а также при следующем запуске после сбоя.

В режиме TUN дополнительно работает служба «LocalProxy TUN» (запускается из LocalProxy, сама не стартует):
она создаёт адаптер «LocalProxy» с маршрутами `0.0.0.0/1` и `128.0.0.0/1` и своим DNS-сервером. При выключении,
выходе или сбое LocalProxy адаптер со всеми маршрутами исчезает. Служба удаляется вместе с программой.
Журнал службы — `C:\ProgramData\LocalProxy\tun.log`.

Настройки лежат в `%APPDATA%\LocalProxy\config.json` (вместе с ключами WireGuard и паролями SSTP — файл не шифруется).

## Ограничения

- **Режим TUN**: нужны права администратора (один раз, на установку службы). Весь трафик, в том числе прямой,
  проходит через программу — на гигабитных загрузках это заметная нагрузка на процессор. Доменные правила
  видят имена из системного DNS; программы со своим DNS (DoH) или вшитыми адресами попадают только под правила
  по подсетям. UDP через канал передают WireGuard, AmneziaWG и SSTP, но не HTTP-прокси. Ping идёт напрямую.
  Может мешать другим VPN-клиентам и программам с собственным виртуальным адаптером.
- **Режим системного прокси**: расширения браузера, управляющие прокси, важнее настроек Windows — пока они
  включены, браузер не применяет правила LocalProxy. Программы без поддержки прокси (Navicat, RDP, игры, голос
  Discord) правила не видят; для подключения к конкретному серверу есть проброс порта (вкладка «Порты»).
- **AmneziaWG 2.0**: такие конфиги подключаются (рукопожатие проходит), но данные не идут. Проверены и работают
  обычный WireGuard и AmneziaWG 3.x.
- **SSTP** несёт только IPv4. Вход по сертификату (EAP-TLS, PEAP) не поддерживается. SSTP — это TCP внутри TCP:
  на линии с потерями он заметно медленнее WireGuard.

## Разработка

Нужны: Rust (stable, MSVC), Go (версия из `tunnel/go.mod`), Node.js 24 и pnpm,
Visual Studio Build Tools с компонентом C++.

```
pnpm install
pnpm tauri dev
```

Устройство:

| Каталог              | Что там                                                                         |
| -------------------- | ------------------------------------------------------------------------------- |
| `crates/proxy-core`  | Прокси: входы HTTP/SOCKS5, правила, PAC, outbound, счётчики трафика             |
| `tunnel`             | Go-программа `localproxy-tunnel`: VPN-туннель в userspace, отдаёт его как SOCKS5 |
| `src-tauri`          | Приложение: трей, системные настройки Windows, наборы, обновления, команды для UI |
| `ui`                 | Интерфейс на Svelte 5                                                            |
| `presets/presets.json` | Наборы доменов; программа скачивает его из ветки `main`                       |

Проверки (то же, что в CI):

```
pnpm check
pnpm test:tunnel
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

### VPN-туннели (`tunnel`)

| Пакет                     | Что там                                                                     |
| ------------------------- | --------------------------------------------------------------------------- |
| `main.go`                 | Обмен с LocalProxy через stdin/stdout, выбор протокола                      |
| `internal/core`           | Общее: сетевой стек gVisor, DNS, SOCKS5-сервер (TCP и UDP), статус          |
| `internal/packet`         | Общий пакетный туннель: перекачка IP-пакетов, keepalive, переподключение    |
| `internal/awg`            | WireGuard / AmneziaWG (свой сетевой стек amneziawg-go)                       |
| `internal/sstp`           | SSTP: TLS, управляющие сообщения, crypto binding; работает поверх `packet`  |
| `internal/ppp`            | PPP-клиент: LCP, вход MS-CHAPv2/PAP, IPCP                                   |
| `internal/mschap`         | MS-CHAPv2 и ключи MPPE                                                       |
| `internal/tun`            | Режим TUN: адаптер Wintun, сетевой стек → SOCKS5 LocalProxy, DNS, ping, смена сети |
| `internal/service`        | Служба Windows для режима TUN: установка, удаление, запуск сеанса            |

`src-tauri/wintun/wintun.dll` — драйвер Wintun 0.14.1 от авторов WireGuard (подписан WireGuard LLC, лицензия рядом);
установщик кладёт его рядом с `localproxy-tunnel.exe`.

Новый протокол, который отдаёт IP-пакеты, реализует `packet.Conn` и функцию подключения — переподключение,
keepalive и SOCKS5 он получает готовыми. Протокол со своим сетевым стеком (как AWG) отдаёт `core.NetTunnel`.

### Наборы доменов

Установленные программы скачивают `presets/presets.json` из ветки `main`. Чтобы изменения дошли до пользователей,
**увеличьте `revision`** в этом файле: программа применяет список, только если его ревизия новее той, что у неё уже есть.
`id` набора не меняйте — по нему хранится выбор пользователя.

### Релиз

1. Поднимите версию в `Cargo.toml` (`[workspace.package] version`) и `package.json`.
2. Добавьте в [CHANGELOG.md](CHANGELOG.md) раздел `## [X.Y.Z] — дата`: его текст станет описанием релиза.
3. Закоммитьте, поставьте тег и отправьте его:

   ```
   git tag v2.2.0
   git push origin v2.2.0
   ```

4. Workflow `Release` проверит, что тег совпадает с версией и что в CHANGELOG есть её раздел, соберёт
   установщик, подпишет его и опубликует релиз с `latest.json`. Установленные копии увидят обновление в течение 6 часов
   или сразу по кнопке «Проверить сейчас».

Обновления подписываются ключом Tauri. Приватный ключ лежит в секретах репозитория
`TAURI_SIGNING_PRIVATE_KEY` (и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`), публичный — в `src-tauri/tauri.conf.json`.
Если ключ потерять, уже установленные копии не примут обновления, подписанные новым ключом: их придётся
переустановить вручную.

Для локальной сборки установщика задайте ключ в переменной среды:

```
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content -Raw "$env:USERPROFILE\.tauri\localproxy.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""
pnpm tauri build
```
