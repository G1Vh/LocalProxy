# Изменения

Формат: раздел на версию, `## [X.Y.Z] — ГГГГ-ММ-ДД`. Текст раздела целиком попадает в описание релиза на GitHub
и в окно обновления программы, поэтому пишется для пользователей. Раздел новой версии добавляется до тега:
релиз без него не соберётся.

## [2.6.1] — 2026-11-14

### Исправлено

- Программы больше не теряют сеть после выхода или сбоя LocalProxy. В режиме TUN LocalProxy не меняет настройки
  прокси Windows и не ставит `HTTP_PROXY`/`HTTPS_PROXY`, галочка переменных в этом режиме снимается сама.
  Раньше программы, запущенные при включённом LocalProxy (например, Claude), после его выхода стучались
  в закрытый порт, пока их не перезапустишь. Один раз после обновления их ещё нужно перезапустить.
- При выключении режима TUN соединения через адаптер обрываются сразу, и программы переподключаются напрямую,
  а не ждут тайм-аута.
- Если DNS не ответил, программа получает ошибку и спрашивает снова, а не поддельный адрес, который переставал
  работать после выхода LocalProxy.

## [2.6.0] — 2026-11-14

### Новое

- **Управление через MCP** для ИИ-агентов (Claude Code, Claude Desktop и другие): «Настройки» → «Управление
  через MCP». Агент видит состояние, ленту подключений и трафик, проверяет, куда пойдёт адрес, добавляет и убирает
  правила, выбирает наборы и каналы, включает и выключает прокси. Кнопка рядом копирует команду подключения
  для Claude Code. Сервер работает только на этом компьютере, по токену, и закрыт для веб-страниц. По умолчанию
  выключен.

## [2.5.0] — 2026-11-14

### Наборы доменов

- Наборы переехали на свою вкладку «Наборы»: по группам (ИИ, Разработка, Видео, Общение, Работа), с поиском
  по названию или домену, каналом и срабатываниями у каждого. Вкладка «Правила» стала короче.
- Новые наборы: Grok / xAI, Gemini Notebook (бывший NotebookLM), JetBrains, Notion.
- Наборы точнее: только нужные адреса, без общих доменов. GitHub Copilot больше не захватывает весь GitHub,
  Gemini дополнен служебными адресами приложения и AI Studio.

### Окно

- Окно запоминает размер и положение. По умолчанию оно выше, чтобы все наборы помещались.

## [2.4.0] — 2026-11-14

### Режим TUN быстрее

- Прямой трафик почти не нагружает компьютер: на скачивании в несколько потоков LocalProxy тратит в пять раз
  меньше процессора, чем раньше, а скорость и время открытия соединения — как без LocalProxy.
- Соединения, которые по правилам идут напрямую, больше не делают круг через LocalProxy, а сразу уходят в сеть,
  и TCP, и UDP. Лента подключений и статистика трафика показывают их как прежде, вместе с ошибками.
- Обновлён сетевой стек режима TUN: исправления для быстрых каналов и каналов с потерями.

### Интерфейс

- Тема окна в настройках: как в Windows, светлая или тёмная. Заголовок окна меняется вместе с ней.
- Настройки занимают всю ширину окна; версия программы — только в строке внизу.

## [2.3.1] — 2026-11-13

### Интерфейс

- Лишние записи можно скрыть из ленты подключений: кнопка «Скрыть» в строке, выбор по программе, адресу и порту,
  по умолчанию только ошибки. Например, программа, которая всё время стучится на закрытый порт, больше не засоряет

  и статистику это не влияет.

## [2.3.0] — 2026-11-13

### Новое

- **Режим «Весь трафик (TUN)»** — теперь основной. Виртуальный адаптер забирает трафик всех программ, и правила
  действуют для любой из них, даже если программа не умеет работать через прокси: игры, мессенджеры,
  клиенты баз данных. Внутренние имена вроде `mysql.office.lan` работают и здесь. Ping отвечает по-настоящему.
  При смене сети (Wi-Fi вместо кабеля) всё переключается само. Прежний режим остался: «Системный прокси»
  в настройках.
- Для TUN ставится служба «LocalProxy TUN»: права администратора Windows спросит один раз, при первом включении.
  Служба запускается только вместе с LocalProxy и удаляется вместе с программой. Если TUN не включился,
  LocalProxy работает как системный прокси и показывает причину.
- **Правила по программам**: тип «программа» — `discord.exe`, маска `steam*.exe` или полный путь. Весь трафик
  программы идёт по правилу, куда бы она ни обращалась; такое правило важнее правил по адресам. В режиме
  системного прокси действует только для программ, которые ходят через LocalProxy.

### Интерфейс

- В ленте подключений видно, какая программа открыла соединение; по ней можно фильтровать, а кнопка «+»
  рядом добавляет программу в правила. «Вставить списком» понимает строки вида `discord.exe`.
- Вкладка «Порты» видна только в режиме системного прокси: в TUN она не нужна.

## [2.2.0] — 2026-11-13

### Новое

- **Проброс портов** — вкладка «Порты» для программ без поддержки прокси: Navicat, DBeaver, RDP, SSH. Программа
  подключается к `127.0.0.1:порт`, LocalProxy ведёт соединение к серверу через выбранный канал. Внутренние имена
  вроде `mysql.office.lan` разрешаются на стороне канала. Если канал недоступен, соединение закрывается.
- **Набор Netflix**.

### Интерфейс

- Вкладка «Outbound» теперь «Каналы», и в подписях везде «канал».
- Окно сужается и растягивается без поломок: шапка переносится, прокрутка одна, таблицы подстраиваются под ширину.
- Наборы доменов сворачиваются в одну строку; состав набора открывается в отдельном окне с поиском.
- Подписи и подсказки стали короче.

## [2.1.0] — 2026-11-13

### Новое

- **Раздельное туннелирование**: у каждого правила и набора доменов может быть свой outbound — например, домены
  офиса через SSTP, YouTube через WireGuard, остальное из правил через outbound по умолчанию. Нужные туннели
  подключены одновременно. В правиле outbound выбирается в колонке «Куда», у отмеченного набора — рядом с ним.
  Состояние, уведомления, лента подключений и статистика трафика — по каждому outbound отдельно. Если outbound
  недоступен, его домены блокируются или идут напрямую, как настроено, и никогда не уходят через другой.
- **SSTP-outbound**: VPN Windows RRAS, MikroTik, SoftEther. Как и WireGuard, работает внутри программы — без
  драйвера, прав администратора и системного VPN-адаптера. Вход по MS-CHAPv2 или PAP. Сертификат сервера
  проверяет Windows; самоподписанному можно доверять по отпечатку SHA-256 — «Проверить» покажет его и предложит
  кнопку «Доверять этому сертификату». Адреса из правил разрешает DNS, который выдал сервер. После обрыва
  туннель переподключается сам.

### Исправлено

- Туннель (WireGuard, SSTP), который не поднялся при запуске — например, сеть ещё не появилась после входа
  в Windows — или упал позже, теперь запускается снова сам, раз в 30 секунд, а не только после изменения
  настроек. Ошибка запуска показывается один раз, а не на каждую попытку.

## [2.0.0] — 2026-11-13

Программа написана заново (Tauri + Rust вместо .NET-службы).

- Окно с правилами: домен с поддоменами, точное совпадение, маска, подсеть; исключения «напрямую».
- Готовые наборы доменов с подпиской (OpenAI, Anthropic, GitHub, Gemini, YouTube, Telegram, Discord),
  обновляются с GitHub без обновления программы.
- Outbound: HTTP- и SOCKS5-прокси, WireGuard и AmneziaWG. Если outbound недоступен, домены из правил
  блокируются или идут напрямую — на выбор.
- HTTP, HTTPS и SOCKS5 (включая UDP) на одном порту; Windows и браузеры подхватывают правила через PAC.
- Иконка в трее показывает состояние outbound, уведомления о его падении и восстановлении.
- Лента подключений и статистика трафика по адресам.
- Автозапуск при входе в Windows, автообновление.
- Предупреждение о расширениях браузера, которые перекрывают системный прокси.
