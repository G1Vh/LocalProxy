# LocalProxy — инструкции для агентов

Выборочный прокси и VPN-клиент для Windows x64 (другие платформы не поддерживаются и не планируются): ядро на Rust
(`crates/proxy-core`), приложение на Tauri 2 (`src-tauri`) с интерфейсом на Svelte 5 (`ui`), сайдкар на Go
(`tunnel`, `localproxy-tunnel.exe`) для VPN-туннелей и режима TUN. Устройство каталогов, проверки CI и порядок
релиза описаны в [README.md](README.md), раздел «Разработка»: читай его перед первой правкой.

## Язык

- Интерфейс, сообщения об ошибках для пользователя, README и CHANGELOG — по-русски, коротко и для пользователя,
  а не для разработчика. В интерфейсе outbound называется «канал».
- Комментарии в коде и сообщения коммитов — по-английски. Коммит: первая строка-итог, дальше пункты `- ...`
  о том, что изменилось для пользователя и как устроено.

## Сборка и проверки

- Сборке приложения нужен готовый сайдкар: перед `cargo build`/`cargo test` по `src-tauri` выполни
  `pnpm build:tunnel` (и `pnpm build` для `dist`), иначе build script приложения упадёт.
- Перед коммитом прогони все проверки из README («Проверки (то же, что в CI)»), включая `pnpm test:tunnel`.
- Релизная сборка для ручной проверки: `pnpm build:tunnel`, затем `pnpm tauri build --no-bundle`; результат —
  `target\release\localproxy.exe`. Запущенный LocalProxy держит свои exe: останови его перед пересборкой.

## Тесты

- Rust: модульные тесты лежат в отдельном файле `<модуль>/tests.rs` (например, `src-tauri/src/events/tests.rs`),
  в коде модуля в конце только `#[cfg(test)] mod tests;`. Сквозные тесты ядра (настоящий прокси на loopback) —
  в `crates/proxy-core/tests/proxy.rs`.
- Go: `*_test.go` рядом с кодом. Тесты, которым нужны права администратора, сеть или запущенный LocalProxy,
  сами пропускают себя (`t.Skip`), когда условий нет; на runner'ах GitHub всё идёт с правами администратора.

## Релиз

Порядок — в README («Релиз»). Сверх него: пример тега в README тоже обновляется до новой версии; исправления

## Режим TUN и служба

- Режим TUN (по умолчанию) работает через службу Windows `LocalProxyTun`: LocalSystem, ручной запуск, exe — тот
  `localproxy-tunnel.exe`, рядом с которым стоял LocalProxy при установке службы. У отладочной сборки это
  `target\release`; LocalProxy сам переустанавливает службу, если путь не совпадает.
- Лог службы — `C:\ProgramData\LocalProxy\tun.log`; конфиг приложения — `%APPDATA%\LocalProxy\config.json`.
- Служба отдаёт каждое соединение в SOCKS5-порт LocalProxy; программу-владельца она передаёт входом SOCKS5
  с пользователем `process` и паролем — путём к exe.
- Против петли прямые сокеты LocalProxy, DNS и туннелей привязываются к физическому интерфейсу (`IP_UNICAST_IF`);
  loopback остаётся непривязанным.
- На машине владельца права администратора повышаются без окна UAC (`ConsentPromptBehaviorAdmin=0`): отсутствие
  окна при установке службы — норма.
